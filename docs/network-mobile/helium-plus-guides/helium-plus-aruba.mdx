## Prerequisites

- Aruba system must be running
  [AOS 8.10.x.x](https://arubanetworking.hpe.com/techdocs/ArubaOS/Consolidated_8.x_RN/Content/8.10/overview-8100x.htm)
  or later (tested on an Aruba 7005 running AOS 8.10.0.16).
- Guide assumes the network is using an on-prem Aruba Mobility Controller.
- Aruba system has AP(s) linked to the Mobility Controller.
- Aruba system has basic traffic routing working with existing SSID(s).
- SSH or console access to the Mobility Controller, to enable RadSec from the CLI.
- The Helium RadSec certificates from the Helium onboarding process (either from the WiFi Conversion
  process or sent to you by your Helium Plus contact): the RadSec Server CA (`ca.pem`), and the
  client certificate and key combined in one PEM file (for example:
  `cat cert.pem key.pem > client_combined.pem`).
- ACLs or firewalls allow the Mobility Controller to reach the internet on TCP port 2083.

## High Level Steps

1. Upload Helium RadSec Certificates
2. Create the Helium RadSec Server
3. Build Helium Passpoint SSID
   1. Build WLAN
   2. Link AAA Profile to RADIUS Accounting Server Group
   3. Build ANQP Profile
   4. Build Advertisement Profile
   5. Link ANQP Profile to the Advertisement Profile
   6. Build Hotspot 2.0 Profile
   7. Link Advertisement Profile to Hotspot 2.0 Profile
   8. Link Hotspot 2.0 Profile to Virtual AP
4. Connect and Validate

## Upload Helium RadSec Certificates

Navigate to **Configuration → System → Certificates → Import Certificates** and add:

- RadSec Server CA (`ca.pem`): Type `TrustedCA`, Format `PEM`
- Combined client certificate and key: Type `ServerCert`, Format `PEM`

Deploy the pending changes. Note the names you give each certificate; you need them in the next
step.

## Create the Helium RadSec Server

Uploading the certificates in the web UI only stores them on the controller. The
`radsec-trusted-cacert-name` and `radsec-client-cert` lines below attach them to the RadSec server;
without them, both certificate fields show `N/A` and the TLS connection to Helium cannot start.

The RADIUS server form in the controller's web UI has no RadSec or certificate fields, and the web
UI has no CLI console. Enable RadSec over SSH (`ssh admin@<controller-ip>`) or the console port:

```
configure terminal
aaa authentication-server radius Helium-RadSec
  host radius-bf.wifi.hellohelium.com
  enable-radsec
  radsec-port 2083
  radsec-trusted-cacert-name <ca-cert-name>
  radsec-client-cert <client-cert-name>
  nas-identifier <your-nas-id>
  key radsec
exit
write memory
```

- Enter the server lines while the prompt shows `(RADIUS Server "Helium-RadSec")`. Commands entered
  at the `(config)` prompt are rejected.
- The client certificate keyword is `radsec-client-cert`. `radsec-client-cert-name` is not accepted.
- `enable-radsec` warns that a trusted certificate is required until `radsec-trusted-cacert-name` is
  set. This is expected.
- Idle SSH sessions time out after a few minutes. If you see `*** IDLE TIMEOUT ***`, reconnect
  before pasting commands.

Verify the configuration:

```
show aaa authentication-server radius Helium-RadSec
```

A working configuration looks like this (example output from an Aruba 7005 on AOS 8.10.0.16; your
NAS ID and certificate names will differ):


This command shows configuration only. To confirm the RadSec session to Helium is up, check
**Diagnostics → Logs** for repeated `Failed to open TLS socket for server Helium-RadSec` errors;
once the connection is established they stop.

## Link AAA Profile for RADIUS Accounting Server Group

1. Click on **Configuration** and then **Authentication** in the left menu column.
2. Click on **AAA Profiles** in the top menu bar
3. Click the **\+** next to **AAA** and **\+** next to **Helium_aaa_prof**
4. Click on **RADIUS Accounting Server Group**
5. Select **Helium_dot1_svg** from the drop-down menu next to **Server Group**

## Connect and Validate

Connect a client device to the newly created SSID.

Verify successful authentication: **Diagnostics → Logs** should no longer show
`Failed to open TLS socket for server Helium-RadSec` errors, and the device should get an IP address
and internet access.

## Troubleshooting

- APs discover the controller but stay `Down`, or RadSec traffic cannot reach Helium: this often
  happens on a controller previously configured for another network. Confirm that **Configuration →
  System → General → Controller IP address** is on a VLAN that both your APs and the internet can
  reach. Changing the controller IP requires a reboot.

<figure className="screensnippet-wrapper">
  <img
    src={useBaseUrl('img/mobile-data-only/aruba-mobility/3-controller-ip.jpg')}
    style={{ maxHeight: '500px' }}
    className="add-border-radius add-shadow add-shadow-margin"
  />
  <figcaption>Controller IP address under System → General.</figcaption>
</figure>

- Clients connect but have no internet access: confirm that the VLAN assigned to the Helium WLAN
  gives clients a routable address with internet access.
- RadSec connection: go to **Diagnostics → Logs**. `TCP connect to server Helium-RadSec failed`
  means the controller cannot reach Helium on TCP 2083. If TCP connects but TLS still fails, recheck
  the CA and client certificate names on the server.
- Certificate import fails with `Certificate is not yet valid`: the controller clock is behind the
  certificate's start date. Check **Configuration → System → General → Clock**; if it uses NTP, make
  sure an NTP server is listed, then deploy and re-import.
- RadSec connects but phones are rejected:
  - Make sure the NAS-ID has been onboarded to the Helium Network
  - Double-check ANQP profile creation steps
