## Prerequisites

- ExtremeCloud IQ is running on your Extreme system.
- An on-prem Extreme controller is in use for the network.
- At least one access point is linked to that controller.
- Existing SSID(s) already have basic traffic routing in place.
- You have an Intel-based host on the network for the RadSecProxy container.
- RadSecProxy is deployed and running before you configure Extreme. See
  [Deploy RadSecProxy Container](#deploy-radsecproxy-container) for deployment steps.

---

## High-Level Steps

1. Deploy the RadSecProxy container and note the host's IP address.
2. Set up the wireless LAN: create an SSID and point its RADIUS servers at RadSecProxy.
3. Configure Hotspot 2.0 for Passpoint.
4. Deploy the configuration to your access points.
5. Verify the configuration on the AP and test Passpoint connectivity.

---

## Deploy RadSecProxy Container

RADIUS messages used to authenticate users and for session accounting are transmitted unsecured over
UDP by default. By directing these messages internally in your secure network to a RadSecProxy, the
UDP traffic is then converted to a TLS-protected TCP connection to the Helium Network core AAA
servers.

### RadSecProxy Prerequisites

- An Intel-based machine with Docker installed.
- The Intel-based machine has a private IP in your network reachable from your Extreme controller.
- ACLs or firewalls allow the Extreme controller and Docker container to communicate via UDP on
  ports 1812 and 1813.
- ACLs or firewalls allow the container/host to reach the internet on TCP ports 2083 and 3802.

### RadSecProxy Container Deployment

1. Unzip and untar the `radsec-proxy-main.tar.gz` file into a directory of your choice on the host
   machine. This will unpack:
   - `Dockerfile` - The Docker instructions to build the container
   - `radsecproxy.conf` - Pre-populated to connect to Helium Network AAA servers
   - `docker-compose.yml` - File to start and stop the container as a daemon

   ```bash
   tar -xvzf radsec-proxy-main.tar.gz
   ```

2. Into the same directory, copy the three certificates obtained from Helium Network:
   - `ca.pem` - The root CA certificate
   - `cert.pem` - The user certificate
   - `key.pem` - The key file matched to the certificate

3. Start the container using:

   ```bash
   sudo docker compose up -d
   ```

4. To stop the container:

   ```bash
   sudo docker compose down
   ```

5. Record the private IP address of the RadSecProxy host machine. You'll use this IP when
   configuring RADIUS servers in your Extreme controller.

### Add RadSec Authentication Servers to the Network Policy

The controller will talk to your RadSecProxy; RadSecProxy then sends RADIUS over TLS to Helium. Use
the RadSecProxy host's private IP or hostname from
[Deploy RadSecProxy Container](#deploy-radsecproxy-container).

Add a RADIUS server group and add your RadSecProxy host to it. The APs send standard RADIUS over UDP
(ports 1812 and 1813) to RadSecProxy, and RadSecProxy handles the TLS connection to Helium, so your
Extreme APs and controller do not need native RadSec support.

1. On the **Wireless Networks** screen, scroll to **Authentication Settings**.
2. Under **Authenticate via RADIUS Server**, click **+** to create a RADIUS server group. The
   **Configure RADIUS Servers** dialog opens.
3. Give the group a name (e.g. `Helium_radsec_group`).
4. Click **Settings** next to the group. In **Select RADIUS Settings**, set **Accounting interim
   update interval** to `300` seconds, then click **Save RADIUS Settings**. You are back in
   Configure RADIUS Servers.
5. Click **+** under **External RADIUS Server**. A **New External RADIUS Server** block appears.
   <figure className="screensnippet-wrapper">
     <img
       src={useBaseUrl('img/mobile-data-only/extreme/extreme-configureradius.png')}
       style={{ maxHeight: '500px' }}
       className="add-border-radius add-shadow add-shadow-margin"
     />
   </figure>
   <br />
6. Set a **Name** (e.g. `primary_radius`).
7. Click **+** beside **IP/Host Name**, choose **IP Address**, and in the **New IP Address or Host
   Name** dialog set an object **Name** (e.g. `Primary`).
8. In **IP/Host Name**, enter your RadSecProxy address and port `1812` (e.g. `192.168.1.100`). Click
   **Save IP Object**. The new server section now shows that IP/host object.
9. Set **Shared Secret** to `mysecret` (the default in the Helium RadSecProxy container).
10. Click **Save External RADIUS**. Back on Configure RADIUS Servers, the new server (e.g.
    `primary_radius`) is listed.
11. Check the box for that server so it is included in the group, then click **Save RADIUS**. You
    return to Authentication Settings with the new group and server shown.
12. Click **Save** (bottom right) to store the network policy. You are back on Wireless Networks
    with your new SSID listed.

### Assign the SSID to the Network Policy

1. On the **Wireless Networks** page, check the box for your SSID (e.g. `Helium`).
2. Click **Next** (bottom right) to attach that SSID to the network policy.

Wireless LAN and policy setup are done.

## Configure Hotspot 2.0

Hotspot 2.0 (Passpoint) lets devices automatically connect to your Wi-Fi when they are in range.
ExtremeCloud IQ uses the supplemental CLI for Hotspot 2.0; you type or paste commands in the GUI.
Prepare the CLI in a text file first so you can paste it when you enable the supplemental CLI.

### Compose Your CLI

Put the following in a text file so you can paste it into the Supplemental CLI later. These commands
tie your network policy to Hotspot 2.0.

1. **Hotspot profile and network type**  
   Create a profile (e.g. `Helium-profile`) with an ANQP domain ID and network type. Use
   `anqp-domain-id 0` so ANQP is scoped to this AP. Use network type `2` for a chargeable public
   network with internet access.

```
   hotspot profile Helium-profile
   hotspot profile Helium-profile anqp-domain-id 0
   hotspot profile Helium-profile network-type 2 access-internet
```

2. **Operator and language**  
   Set the operator name (e.g. `Helium-Operator`) and language (e.g. English).

```
   hotspot profile Helium-profile operator-name Helium-Operator language-code eng
```

3. **IP support**  
   Use IPv4 with double-NAT private addressing (`ip-type ipv4 2`) and no IPv6 (`ipv6 0`).

```
   hotspot profile Helium-profile ip-type ipv4 2 ipv6 0
```

4. **Domains**  
   Add both Helium Passpoint domains:

```
   hotspot profile Helium-profile domain-name freedomfi.com
   hotspot profile Helium-profile domain-name hellohelium.com
```

For carrier offload, also add one `domain-name` line for each carrier domain your site is approved
for. The carrier domains are provided during Helium Plus onboarding.

```
   hotspot profile Helium-profile domain-name <carrier-domain>
```

5. **NAI realms**  
   Define NAI realms for Helium Passpoint with encoding type `0`, EAP method `13` (EAP-TLS), and
   certificate as the authentication method.

```
   hotspot profile Helium-profile nai-realm freedomfi.com encoding-type 0
   hotspot profile Helium-profile nai-realm freedomfi.com eap-method 13
   hotspot profile Helium-profile nai-realm hellohelium.com encoding-type 0
   hotspot profile Helium-profile nai-realm hellohelium.com eap-method 13
```

6. **NAS-ID**  
   Set the NAS-Identifier the AP sends in its RADIUS requests. Helium uses it to identify your site,
   so use the NAS ID assigned to the site during Helium Plus onboarding, exactly as provided.

```
   aaa attribute NAS-Identifier <your-nas-id>
```

7. **SSID security**  
   Set the SSID to use WPA3-AES 802.1X:

```
   security-object Helium security protocol-suite wpa3-aes-8021x
```

8. **Attach hotspot profile to SSID**  
   Apply the hotspot profile to the SSID:

```
   ssid Helium hotspot-profile Helium-profile
```

9. **Persist config**  
   Save the configuration:

```
   save configuration
```

:::warning The SSID name in the CLI must match ExtremeCloud IQ

In the `security-object` and `ssid` lines, replace `Helium` with the **SSID Name** you set in
[Create an SSID](#create-an-ssid). It is case-sensitive. If the names differ (for example, an SSID
named `Helium-Extreme` while the CLI says `Helium`), the AP accepts the configuration but the
hotspot profile is never applied to the SSID you are broadcasting.

:::

### Complete CLI Example

The full CLI for an SSID named `Helium`, ready to paste into the Supplemental CLI. Replace the SSID
name, the NAS ID, and the carrier domain placeholder with your own values, and add one `domain-name`
line per approved carrier domain.

```
hotspot profile Helium-profile
hotspot profile Helium-profile anqp-domain-id 0
hotspot profile Helium-profile network-type 2 access-internet
hotspot profile Helium-profile operator-name Helium-Operator language-code eng
hotspot profile Helium-profile ip-type ipv4 2 ipv6 0
hotspot profile Helium-profile domain-name freedomfi.com
hotspot profile Helium-profile domain-name hellohelium.com
hotspot profile Helium-profile domain-name <carrier-domain>
hotspot profile Helium-profile nai-realm freedomfi.com encoding-type 0
hotspot profile Helium-profile nai-realm freedomfi.com eap-method 13
hotspot profile Helium-profile nai-realm hellohelium.com encoding-type 0
hotspot profile Helium-profile nai-realm hellohelium.com eap-method 13
aaa attribute NAS-Identifier <your-nas-id>
security-object Helium security protocol-suite wpa3-aes-8021x
ssid Helium hotspot-profile Helium-profile
save configuration
```

### Apply the Hotspot 2.0 Configuration to the Network Policy

Depending on your ExtremeCloud IQ version, the Supplemental CLI for a network policy is in one of
two places:

- **Configure** → **Network Policies** → your policy → **Wireless** → **Supplemental CLI**.
- **Configure** → **Network Policies** → your policy → your SSID → **Additional Settings** →
  **Policy Settings** → **Supplemental CLI**.

Both edit the same Supplemental CLI object. The steps below use the SSID path.

1. Go to **Configure** → **Network Policies**. Open your policy (e.g. `Helium_network_policy`).
2. Click your SSID name (e.g. `Helium`) to open the Wireless Network page.
3. Open **Additional Settings** in the top bar (e.g. you may see the DNS Server page).
4. Under **Policy Settings** on the left, open **Supplemental CLI**.
5. Ensure **Supplemental CLI** is enabled on this page.
   <figure className="screensnippet-wrapper">
     <img
       src={useBaseUrl('img/mobile-data-only/extreme/extreme-supplementalcli.png')}

       className="add-border-radius add-shadow add-shadow-margin"
     />

   <br />
6. Enter a **Name** (e.g. `Hotspot`) and paste your CLI commands into **CLI Commands**.
7. If you see the **Supplemental CLI overrides UI** option, enable it so the CLI settings take
   precedence over any conflicting settings made in the UI.
8. Click **Save** (bottom right). A confirmation appears that the supplemental CLI was saved.
9. Click **Next** to open **Apply the network policy to selected devices**.
10. Click **Eligible** to list access points, then select the APs you want (checkboxes in the
    **Status** column).
11. Click **Upload** (bottom right). The **Device Update** dialog opens.

after the AP is back up. Rather than waiting on that status, watch the AP's **Uptime** in **Manage**
→ **Devices**: when it resets to a few minutes, the AP has rebooted with the new configuration. If
the uptime never resets and the update does not activate, reboot the AP from ExtremeCloud IQ and
check again.

## Verify the Configuration

IQ Engine silently drops any Supplemental CLI line it does not accept, and ExtremeCloud IQ still
reports the update as successful. After every update, confirm on the AP that each line was applied:

1. Go to **Manage** → **Devices** and select the AP.
2. Open **Utilities** → **Diagnostics** → **Show Running Config**.
3. Check that every line from your CLI appears in the output, in particular the `hotspot profile`,
   `aaa attribute NAS-Identifier`, `security-object`, and `ssid ... hotspot-profile` lines. If a
   line is missing, correct its syntax (or the SSID name) and push a complete configuration update
   again.

To confirm a Passpoint client is connected, connect a device with a Helium or carrier Passpoint
profile near the AP, then open **Manage** → **Clients**. The device should be listed on your SSID,
and its user name shows the Passpoint realm it authenticated with.

:::tip Recovering a carrier Passpoint network on Android

If you tap **Forget** on a carrier Passpoint network on an Android phone during testing, the phone
stops joining it automatically. To get it back, go to **Settings** → **Network & internet** →
**Internet**, tap the network name in the list, and tap **Connect**. Android re-enables automatic
connection for that network.

:::

## Multi-Site Deployments

Each site needs its own NAS ID, but you do not need a separate network policy per site. Use one
network policy with the shared Hotspot 2.0 CLI, and set the NAS ID per AP:

1. Keep the network policy's Supplemental CLI free of the `aaa attribute NAS-Identifier` line.
2. For each AP, go to **Manage** → **Devices**, open the AP, and add a device-level Supplemental CLI
   containing only that site's `aaa attribute NAS-Identifier <site-nas-id>` line.
3. On the device-level Supplemental CLI, choose the option to **Keep Supplemental CLI** from the
   network policy **and append** the device CLI, so the AP gets the shared Hotspot 2.0 lines plus
   its own NAS ID.
4. Push a complete configuration update and [verify](#verify-the-configuration) the running config
   on one AP per site.

Alternatively, AP Templates combined with location-based rules can assign per-site settings, but
this approach has not been validated for NAS IDs.
