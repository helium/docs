## Prerequisites

- Meraki system must be running
  [14.0](https://documentation.meraki.com/General_Administration/Firmware_Upgrades/Cisco_Meraki_Firmware_FAQ)
  or later.
- Guide assumes the network is using an on-prem Meraki MX Controller.
- Meraki system has AP(s) linked to the MX Controller.
- Meraki system has basic traffic routing working with existing SSID(s).
- An Intel-based host is required in the network to run the
  [RadSecProxy](https://github.com/novalabsxyz/radsec-proxy) container.

## High Level Steps

1. Deploy RadSecProxy container and record IP address of host
2. Build Meraki Helium Passpoint SSID
   1. Build a new SSID
   2. Configure SSID to use RADIUS
   3. Build Hotspot 2.0 Profile

## Deploy RadSecProxy Container

RADIUS messages used to authenticate users and for session accounting are transmitted unsecured and
over UDP by default. By directing these messages internally in your secure network to a RadSecProxy,
the UDP is then converted to a TLS-protected TCP connection to the Helium Network core AAA servers.

### Prerequisites

- An Intel-based machine with Docker installed.
- The Intel-based machine has a private IP in your network reachable from your Meraki Mobility
  Controller.
- ACLs or firewalls allow the Meraki Mobility Controller and Docker container to communicate over
  UDP on ports 1812 and 1813.
- ACLs or firewalls allow the container/host to reach the internet on TCP port 2083.

### Container Deployment

1. Unzip and untar the `radsec-proxy-main.tar.gz` file into the directory of your choice on the host
   machine. This will unpack the following items:
   1. `Dockerfile` \- The Docker instructions on how to build the container
   2. `radsecproxy.conf` \- The radsecproxy config file is pre-populated to connect to Helium
      Network AAA servers
   3. `docker-compose.yml` \- File to start and stop the container as a daemon.

```bash
tar -xvzf radsec-proxy-main.tar.gz
```

2. Into the same directory copy the 3 certificates obtained from the Helium Network
   1. ca.pem - the root CA certificate
   2. cert.pem - the user certificate
   3. key.pem - the key file matched to the certificate
3. Start the container using:

```bash
sudo docker compose up -d
```

4. If/when needed, stop the container using:

```bash
sudo docker compose down
```

### Configure Helium SSID for RADIUS Access Control

:::note

Helium is aware that Meraki has some native support for RadSec. Unfortunately, the Meraki
implementation is not scalable for a network like Helium. Meraki builds a CA certificate specific to
each group of APs and asks for it to be loaded on the AAA. That does not scale and there is no way
to load the client certificate and key Helium produces during onboarding into the Meraki RadSec
client. So for now the guide below uses our RadSecProxy container and plain RADIUS configuration on
the Meraki devices.

:::

1. Click **Edit Settings**
2. Under the **Security** heading, toggle the circle **Enterprise with**
3. Select **my RADIUS Server**
   <figure className="screensnippet-wrapper">
     <img
       src={useBaseUrl('img/mobile-data-only/meraki/Meraki-figure-4.png')}
       style={{ maxHeight: '500px' }}
       className="add-border-radius add-shadow add-shadow-margin"
     />
   </figure>
4. Scroll down to **RADIUS** and click the arrow on the right to expand
5. Click add server and add the following configurations
   1. Enter IP Address: **\<ip of your radsecproxy container host\>**, Port: **1812**, Secret:
      **mysecret**. Click **Done**.
   2. Add a second server if desired for HA redundancy.
      <figure className="screensnippet-wrapper">
        <img
          src={useBaseUrl('img/mobile-data-only/meraki/Meraki-figure-5.png')}
          style={{ maxHeight: '500px' }}
          className="add-border-radius add-shadow add-shadow-margin"
        />
      </figure>
6. Repeat those steps to add the same server to the RADIUS Accounting Servers list using
   **port 1813.**
   <figure className="screensnippet-wrapper">
     <img
       src={useBaseUrl('img/mobile-data-only/meraki/Meraki-figure-6.png')}
       style={{ maxHeight: '500px' }}
       className="add-border-radius add-shadow add-shadow-margin"
     />
   </figure>
7. Select the check box next to **Radius CoA Support**
   <figure className="screensnippet-wrapper">
     <img
       src={useBaseUrl('img/mobile-data-only/meraki/Meraki-figure-7.png')}
       style={{ maxHeight: '500px' }}
       className="add-border-radius add-shadow add-shadow-margin"
     />
   </figure>
8. Click on the arrow to expand the **Advanced RADIUS settings** section
9. Change the number 1 dropdown for **NAS ID** to **Custom** and enter the NAS-ID you got during
   onboarding
10. Click the **×** to remove number 2 in that list, which says **SSID Number**
    <figure className="screensnippet-wrapper">
      <img
        src={useBaseUrl('img/mobile-data-only/meraki/Meraki-figure-8.png')}
        style={{ maxHeight: '450px' }}
        className="add-border-radius add-shadow add-shadow-margin"
      />
    </figure>
11. Click **Save**

:::warning

The NAS-ID Meraki transmits must match the NAS-ID registered with Helium exactly, character for
character. A difference in separators alone is enough to fail authentication, so leave the number 1
drop down on **Custom** and enter the NAS-ID from onboarding.

If you select **AP MAC address** as the NAS ID instead, be aware that the format Meraki transmits
depends on how the SSID itself was built:

- On an SSID applied from a **template** across multiple sites, the MAC is sent dash-separated and
  upper case: `E0-CB-BC-48-BC-76`
- On a normal, single-site SSID, the same AP sends the MAC with no separators at all: `E0CBBC48BC76`

Either format works, but the one your SSID actually sends has to be the one registered with Helium.
Moving an SSID between the two afterwards changes the NAS-ID, and the new value has to be
re-registered before those APs will authenticate.

:::

## Quality Metrics Integration

Quality metrics integration lets Helium read Wi-Fi quality metrics from your Meraki organization
through a Meraki integration with the **Helium Wi-Fi Quality Metrics Poller** (**wifi-qm-poller**),
an OAuth app that Helium registered with Cisco. Helium uses these metrics to monitor the Wi-Fi
experience carrier subscribers get on your network. Depending on the venue tier and the partner
carrier's requirements, this integration may be required. Contact the Helium sales team for details
about your site.

You grant the app read-only access once per organization, and it then appears under your
organization's integrations. There is no VPN, no device configuration, and no API key to share.

The app requests only these two read-only telemetry scopes, and nothing else:

- `wireless:telemetry:read`
- `dashboard:general:telemetry:read`

Before you begin, make sure you have:

- **An organization hosted on the US Meraki cloud**. The Dashboard footer shows where your data is
  hosted.
- **Full organization admin** rights in the Meraki Dashboard, to approve the authorization link.

### Share Your Organization Details

Send the following to your Helium Plus contact:

- **Organization ID** (required). It appears in the footer at the bottom of any Meraki Dashboard
  page, for example "Data for Helium (organization ID: 1672666)".
- **Networks** (optional). The names or IDs of the networks to read metrics from. By default, Helium
  reads every network that has wireless APs.
- **SSIDs** (optional). The exact SSID names to read metrics from, case-sensitive. By default,
  Helium reads every SSID.

### Authorize the Metrics Poller

Once your organization is set up on the Helium side, your Helium Plus contact sends you an
authorization link.

1. Have a full organization admin open the link and sign in to Meraki if prompted.
2. Under **Select an organization**, choose the organization whose ID you shared.
3. Review the requested read access: telemetry for **Wireless (MR)** and for the **Entire dashboard,
   excluding identity and access management**. These match the two scopes listed above.
4. Click **Allow**.

match the ID you shared, so contact your Helium Plus contact.

### Verify the Integration

In the Meraki Dashboard, go to **Organization** > **Integrations** and open the **wifi-qm-poller**
integration. It lists the read access you granted, and **Last used** updates as Helium collects
metrics. The first metrics arrive about 15 minutes after approval.

You can revoke access at any time with **Remove** on the same page, which stops quality metrics
collection. Let your Helium Plus contact know that setup is complete. The Helium team will confirm
that quality metrics are flowing from your organization.
