Omada APs send plain RADIUS to a RadSecProxy on your network, and the proxy forwards it to Helium
AAA over RadSec (RADIUS over TLS). The Helium certificates live on the proxy, not on the Omada
controller.

:::note

The Omada controller has a RadSec option, but do not use it for Helium. Many EAP models do not
support RadSec in their current firmware, and the OC200 hardware controller accepts only RSA
certificates, while Helium issues EC certificates. Use RadSecProxy as described below.

:::

## Prerequisites

- An Omada Software Controller, Hardware Controller (e.g. OC200/OC300), or Omada Cloud-Based
  Controller. This guide was built on controller version **6.2.0.17**.
- Omada EAP access point(s) adopted by the controller, running firmware that supports Hotspot 2.0
  (this guide was tested with an **EAP670 v2**).
- Basic traffic routing already working with existing SSID(s).
- A RadSecProxy deployed on your network with the Helium certificates from onboarding (`ca.pem`,
  `cert.pem`, `key.pem`). See
  [Deploy RadSecProxy Container](/mobile/helium-plus-extreme#deploy-radsecproxy-container) for the
  steps and [RadSecProxy](/mobile/helium-plus-radsecproxy) for deployment options.
- ACLs/firewalls allow the EAPs to reach the RadSecProxy on **UDP 1812 and 1813**, and the
  RadSecProxy to reach the internet on **TCP 2083**.
- The NAS-ID you registered with Helium during [onboarding](/mobile/wifi-conversion-onboarding).

## High Level Steps

1. Create a Helium RADIUS Profile that points at your RadSecProxy
2. Build the Omada Helium Passpoint SSID
   1. Build a new SSID
   2. Configure the SSID to use the Helium RADIUS Profile and NAS-ID
   3. Build the Hotspot 2.0 config
3. Connect and validate

:::note

In the following steps we will only mention mandatory fields to set. Most windows will have many
other parameters with default values set. Leave any unmentioned parameter at its default value.

:::

Log in to your Omada Controller and open the site that holds your APs.

## Create the Helium RADIUS Profile

1. In the left menu, click **Network Config** > **Profile** > **RADIUS Profile**.
2. Click **Create New RADIUS Profile**.
3. **Name**: `Helium-RadSecProxy`
4. Leave **VLAN Assignment** and **Require Message-Authenticator** unchecked.
5. Under **Authentication Server 1**:
   1. **Authentication Server IP/URL**: the IP address of your RadSecProxy
   2. **RadSec**: leave unchecked
   3. **Authentication Port**: `1812`
   4. **Authentication Password**: the shared secret from your RadSecProxy configuration (`mysecret`
      is the default in the Helium RadSecProxy container)
6. Under **Accounting Server**, check **Enable** for **RADIUS Accounting** and **Interim Update**.
   Set **Interim Update Interval** to `300` seconds.
7. Under **Accounting Server 1**:
   1. **Accounting Server IP/URL**: the IP address of your RadSecProxy
   2. **RadSec**: leave unchecked
   3. **Accounting Port**: `1813`
   4. **Accounting Password**: the same shared secret
8. Leave **RADIUS Proxy** and **RADIUS CoA** unchecked.
9. Click **Save**.

The RadSecProxy handles the connection to all of Helium's AAA servers, so only one server is needed
here. If you run a second RadSecProxy for redundancy, add it with **Add New Authentication Server**
and **Add New Accounting Server**.

## Build Omada Helium Passpoint SSID

The following steps will configure your Omada system to broadcast an SSID with the needed Passpoint
and RADIUS configurations to support Helium Mobile user offload.

### Configure Helium SSID for RADIUS Access Control

1. **Security**: **WPA-Enterprise**
2. **RADIUS Profile**: `Helium-RadSecProxy`
3. **NAS ID**: select **Custom** and enter the NAS-ID you registered with Helium during onboarding.

:::warning

The NAS-ID must match the NAS-ID registered with Helium **exactly, character for character**. Leave
the selection on **Custom**.

If you choose **Default (TP-Link: MAC Address)** or **Follow Device Name** instead, each AP sends
its own value, and every one of those values must be registered with Helium in the same format the
AP sends.

:::

### Build Hotspot 2.0 Config

Hotspot 2.0 is labeled **Beta** in the Omada controller. It is still the section to use.

1. Expand **Hotspot 2.0** and check **Enable**.
2. **Network Type**: **Chargeable public network**
3. **PLMN ID**: leave blank unless your Helium Plus contact provides carrier PLMN IDs. If they do,
   click **Add** and enter one PLMN per approved carrier.
4. Leave **Roaming Consortium OI** blank.

7. **DGAF Disable**: check **Enable**

10. **Network Availability IPv4**: **Double NATed private IPv4 address available**

## Connect and Validate

1. On the RadSecProxy host, follow the logs with `sudo docker compose logs -f` from the proxy
   directory.
2. Bring a phone with the Helium Mobile app installed near an EAP. It should join the `Helium` SSID
   automatically, without asking for a username or password.
3. The proxy logs should show an Access-Accept for the device, followed by accounting requests.
4. In the Omada controller, **Clients** should list the device on the `Helium` SSID.

## Troubleshooting

- **The phone asks for a username and password:** Hotspot 2.0 is not active on the AP. Check that
  the EAP firmware supports Hotspot 2.0 and update it if not.
- **No requests reach the proxy:** confirm the RADIUS profile points at the proxy's IP, and that UDP
  1812 and 1813 are open between the EAPs and the proxy.
- **Access-Reject:** the NAS-ID does not match the one registered with Helium, or the shared secret
  does not match the proxy configuration.
- **No usage at Helium:** RADIUS Accounting is not enabled in the RADIUS profile.
